    26→🔴 CRITICAL BUG #1 — `public/css/website.css` IS BROKEN AT LINE 1
    27→   The file starts with `};` (orphaned closing brace) and then declares CSS
    28→   custom properties WITHOUT a `:root {` opener. Line 2 contains literal
    29→   Blade syntax `{{ $settings['secondary_color'] ?? '#D97706' }}` and
    30→   `{{ $primaryR }}, {{ $primaryG }}, {{ $primaryB }}` which is served as
    31→   raw text because Blade does NOT process static files in /public/.
    32→   Impact:
    33→   - The entire `:root` block in website.css is dropped by the browser
    34→     (invalid selector + orphan declarations).
    35→   - EVERY rule that references `rgba({{ $primaryR }}, {{ $primaryG }}, {{ $primaryB }}, …)`
    36→     is also dropped — this includes `.navbar`, `.navbar.scrolled`,
    37→     `.page-hero`, and several others. The navbar background, page-hero
    38→     gradient, and mobile-drawer gradient are ALL unstyled on the live site.
    39→   - The layout's inline `<style>` block (in layouts/website.blade.php)
    40→     DOES define `--primary-color`, `--secondary-color`, `--primary-rgb`
    41→     correctly via Blade, so those tokens still resolve — but every
    42→     website.css rule that re-uses Blade `{{ }}` placeholders is dead.
    43→   Fix: rewrite website.css as a plain static CSS file (no Blade). Either
    44→   hardcode the default color values or rely solely on `var(--primary-color)`
    45→   / `var(--primary-rgb)` set by the layout's inline :root block.
    46→
    47→🔴 CRITICAL BUG #2 — TWO CONFLICTING LAYOUTS, NEITHER CONSISTENT
    48→   The project has TWO layout templates for public pages:
    49→   (a) `layouts/website.blade.php`  — used by welcome, about, contact, team,
    50→       gallery. Green + gold theme. Loads Bootstrap 5 + Font Awesome 6.5.1 +
    51→       Montserrat/Playfair fonts + design-tokens.css + website.css (broken).
    52→       NO i18n (all strings hardcoded English). NO language switcher.
    53→   (b) `layouts/app.blade.php`      — used ONLY by `home.blade.php` (the
    54→       emergency fallback homepage). Navy + amber theme. Self-contained
    55→       inline CSS (no Bootstrap). Uses `__('app.*')` translation keys
    56→       throughout. HAS a language switcher dropdown. Modern, polished,
    57→       fully internationalized — but never rolled out to the main pages.
    58→   `home.blade.php` (fallback) uses Bootstrap classes (`.row`, `.col-md-4`,
    59→   `.card`, `.btn-gold`, `.gold-text`, `.hero`, `.stitle`) that are NOT
    60→   defined anywhere — `layouts/app.blade.php` doesn't load Bootstrap, so
    61→   the fallback homepage renders COMPLETELY UNSTYLED.
    62→   Fix: pick ONE layout, consolidate. `layouts/app.blade.php` is the more
    63→   modern, i18n-ready foundation — recommend extending it to all public
    64→   pages and deleting `layouts/website.blade.php` + `website.css`.
    65→
    66→🔴 CRITICAL BUG #3 — `app/download.blade.php` IS A THIRD, OFF-BRAND THEME
    67→   The download page is a 906-line standalone HTML file (no @extends) with
    68→   its own complete inline `<style>` block using an INDIGO (#6366f1) +
    69→   dark-navy (#0f172a) palette, Inter font, and its own navbar/footer.
    70→   It does NOT match the green/gold website theme at all. Users clicking
    71→   "Get App" in the website navbar are jarringly transported to a page
    72→   that looks like a different product.
    73→   Also: `<meta name="theme-color" content="#6366f1">` here vs.
    74→   `#047857` in website layout — browsers will show different
    75→   status-bar colors depending on the page.
    76→
    77→🔴 CRITICAL BUG #4 — NO i18n ON THE PUBLIC WEBSITE
    78→   `lang/en/app.php` and `lang/am/app.php` already define keys for
    79→   `home`, `about`, `gallery`, `contact`, `team`, `quick_links`,
    80→   `programs`, `contact_us`, `all_rights_reserved`, `footer_about`,
    81→   `login`, `school_name`, `brand_pre`, `brand_name`, etc. — but NONE of
    82→   the public views use `__('app.*')`. Every string is hardcoded English.
    83→   The Amharic locale exists but switching to it changes nothing on the
    84→   public site. (Only `layouts/app.blade.php` uses the translations —
    85→   see Bug #2.) The `lang.switch` route exists and works, but is useless
    86→   for public visitors.
